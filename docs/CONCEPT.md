# VPN Rate — концепция

## Зачем

Онлайн-чекеры (например, ip.net.coffee/claude) дают **снимок на одну секунду**: какой у тебя
IP, видны ли утечки, какой «trust score». Но они не видят, что происходит **во времени**:
сколько раз за день отвалился VPN, уходил ли трафик мимо туннеля, когда сменился IP и не
попал ли новый IP в чёрные списки.

VPN Rate — лёгкий фоновый агент для компьютера, который:

1. постоянно следит за стабильностью подключения (обрывы, задержка, потери);
2. при каждой смене сети/IP проверяет «чистоту» выхода в интернет (тип IP, утечки DNS,
   UDP/WebRTC, IPv6, часовой пояс);
3. считает **открытый** рейтинг (формула в коде и в README, в отличие от онлайн-сервисов);
4. показывает всё в маленьком локальном интерфейсе.

Цель проекта — полезный open-source инструмент на GitHub.

## Цели

- **Лёгкость.** Один exe-файл, без рантаймов. ОЗУ ≈ 15–30 МБ, CPU ≈ 0 в простое.
  Сетевые пробы — крошечные TCP-соединения; внешние API дёргаются только при смене IP
  (с кэшем), а не постоянно.
- **Приватность.** Всё хранится локально. Никакой телеметрии. Наружу уходят только запросы
  к публичным сервисам определения IP/репутации.
- **Честный рейтинг.** Открытая формула, каждый штраф объяснён. Явно сказано, что это
  эвристика: Anthropic/OpenAI/Google не публикуют свои критерии.
- **Работает из коробки.** Запустил — появился значок в трее, дашборд по клику.

## Не цели (v1)

- Не VPN-клиент и не «фиксит» утечки — только диагностирует.
- Не сниффер трафика, не требует прав администратора и драйверов.
- Не облачный сервис, нет аккаунтов.
- Не гарантирует, что тебя не забанят.

## Анти-цели (провал, даже если «работает»)

- Агент сам ходит на AI-сайты (claude.ai, chatgpt.com, …). Если VPN упал, такие
  запросы уйдут с реального IP — ровно то, от чего агент должен защищать. Поэтому
  проверки доступности сервисов удалены (решение от 2026-11-16).
- Агент заметно грузит систему или сеть.
- Агент сам долбит сторонние API так, что упирается в их лимиты и выдаёт мусор.
- Рейтинг — «чёрный ящик», которому нельзя доверять.

## Что измеряется

| Проверка | Как | Как часто |
|---|---|---|
| **Связность** | TCP connect к 1.1.1.1:443 и 8.8.8.8:443 (+ 9.9.9.9:443 как запасной). Онлайн, если ответил хоть один. Задержка = время соединения. | каждые 5 с |
| **Обрывы** | Детектор состояний: offline после 2 подряд провалов, online после 1 успеха. Каждое падение — событие с началом, концом, длительностью. | непрерывно |
| **Публичный IPv4 / IPv6** | Несколько источников (ipify, icanhazip, ifconfig.co) с откатом. | каждые 60 с + при смене интерфейсов |
| **Смена IP** | Сравнение с прошлым значением → событие. | — |
| **VPN-интерфейс** | Перечисление сетевых интерфейсов, поиск туннельных (WireGuard, Wintun, TAP, TUN, OpenVPN, Outline, AmneziaWG, Hiddify, sing-box, v2ray и т.д.). Пропажа туннеля → событие «VPN отключился». | каждые 5 с |
| **Информация об IP** | ipapi.is (тип: datacenter/VPN/proxy/Tor/abuser, ASN, страна, часовой пояс) с откатом на ip-api.com. Кэш на IP — 24 ч. | только при смене IP |
| **DNS-утечка** | Резолвим `whoami.akamai.net` системным резолвером — Akamai возвращает IP рекурсивного DNS-сервера, который реально ходит в интернет. Сравниваем его страну/ASN со страной/ASN выходного IP. | при смене IP + раз в 10 мин |
| **UDP / WebRTC-утечка (системная)** | Собственный STUN-запрос (RFC 5389) к stun.l.google.com:19302 и stun.cloudflare.com:3478 → UDP-выходной IP. Если отличается от HTTP-выходного IP — UDP идёт мимо туннеля, а значит WebRTC в браузере тоже «светит». | при смене IP + раз в 10 мин |
| **WebRTC в браузере** | Дашборд сам запускает RTCPeerConnection, собирает кандидаты (host/srflx) и отправляет агенту. | при открытии дашборда |
| **IPv6-утечка** | Если есть IPv6 и его ASN/страна ≠ IPv4 — IPv6 идёт мимо VPN. | при смене IP |
| **Часовой пояс** | Смещение системного часового пояса vs часовой пояс IP. | при смене IP |

## Рейтинг

Две независимые оценки, обе 0–100.

### Trust Score (насколько «чисто» выглядит подключение)

Старт 100, штрафы (не ниже 0):

| Признак | Штраф |
|---|---|
| Tor exit | −50 |
| Страна выхода в списке неподдерживаемых AI-сервисами (RU, BY, CN, HK, MO, IR, KP, SY, CU) | −40 |
| IP помечен как abuser / в чёрных списках | −25 |
| IP датацентра/хостинга | −20 |
| IP помечен как известный VPN | −10 |
| IP помечен как прокси | −10 |
| DNS-утечка (страна DNS-резолвера ≠ страна выхода; публичные anycast-DNS — Google, Cloudflare, Quad9, OpenDNS, AdGuard, NextDNS — из соседней страны не считаются, если это не страна из списка неподдерживаемых) | −15 |
| UDP/WebRTC-утечка (STUN IP ≠ HTTP IP) | −15 |
| IPv6-утечка | −15 |
| Часовой пояс системы ≠ часовой пояс IP (разница > 1 ч) | −10 |

Грейд: 85–100 «Отлично», 70–84 «Хорошо», 50–69 «Подозрительно», < 50 «Высокий риск».

### Stability Score (за последние 24 ч)

`100 − (простой% × 2) − 3 × (число обрывов, макс. 30) − 1 × (число падений VPN-туннеля, макс. 20) − штраф за задержку (p95 > 300 мс: −5, > 800 мс: −10)`, не ниже 0.

## Интерфейс

- **Значок в трее** — цветной кружок: зелёный (всё хорошо), жёлтый (подозрительно/
  нестабильно), красный (нет сети или высокий риск). Меню: текущий IP, Trust, Stability,
  «Открыть дашборд», «Перепроверить», «Автозапуск ✓», «Выход».
- **Дашборд** — локальная веб-страница `http://127.0.0.1:8737` (только loopback),
  одна HTML-страница, встроенная в exe: две оценки с разбором штрафов, текущий выход
  (IP, ASN, страна, тип), утечки, полоса доступности за 24 ч, лента событий, проверка
  WebRTC в браузере.
- **Уведомления Windows** — при обрыве > 30 с, отключении VPN-туннеля, смене IP,
  обнаружении утечки.

## Хранение

`%APPDATA%\vpnrate\`:
- `events.jsonl` — события (обрывы, смена IP, утечки, VPN up/down), append-only,
  хранятся 30 дней;
- `samples-YYYY-MM-DD.jsonl` — поминутные агрегаты проб (онлайн-доля, средняя/p95
  задержка), 30 дней;
- `ipcache.json` — кэш информации об IP;
- `config.json` — порт, интервалы, включены ли уведомления.

## Технологии (решения разработчика)

- **Go** — один статический exe ~10 МБ, низкое потребление памяти, без cgo
  (на машине нет gcc, и это упрощает сборку другим людям).
- **fyne.io/systray** — трей без cgo.
- **golang.org/x/sys/windows/registry** — автозапуск через `HKCU\...\Run` (без прав админа).
- **go-toast** — уведомления Windows.
- Без БД: JSONL-файлы.
- Ядро кроссплатформенное; трей/автозапуск/уведомления — за build-тегами, v1 тестируется
  на Windows.

## Архитектура

```
cmd/vpnrate/main.go      — запуск, флаги (-headless, -port, -data)
internal/probe           — TCP-пробы, детектор обрывов (state machine)
internal/netif           — перечисление интерфейсов, детект VPN-туннелей
internal/publicip        — публичный IPv4/IPv6 с откатом источников
internal/ipinfo          — ipapi.is / ip-api.com, нормализация, кэш
internal/leak            — DNS (whoami.akamai.net), STUN-клиент, IPv6, timezone
internal/score           — Trust и Stability, чистые функции
internal/store           — JSONL события/сэмплы, ротация
internal/monitor         — оркестратор: расписание, состояние, события
internal/web             — HTTP API + встроенный дашборд
internal/ui              — трей, уведомления, автозапуск
```

HTTP API: `GET /api/status`, `GET /api/events?since=`, `GET /api/samples?hours=24`,
`POST /api/recheck`, `POST /api/webrtc` (результат браузерной проверки).

## Тесты (написаны до кода)

Юнит-тесты (`go test ./...`), без сети — внешние сервисы подменяются `httptest`/локальным UDP:

1. **score** — табличные тесты Trust: чистый домашний IP = 100; датацентр + VPN = 70;
   Tor + RU = 10; все штрафы → 0 (не уходит в минус); грейды на границах.
   Stability: идеальные сутки = 100; 1 % простоя + 2 обрыва = 92; p95-штраф.
2. **probe** — детектор обрывов: один провал не открывает обрыв; два подряд — открывают
   с временем первого провала; успех закрывает и считает длительность; uptime% по окну.
3. **netif** — классификация имён интерфейсов: «WireGuard Tunnel», «Wintun», «TAP-Windows
   Adapter V9», «OpenVPN Data Channel Offload», «AmneziaWG» → туннель; «Wi-Fi»,
   «Ethernet», «vEthernet (WSL)» → нет.
4. **publicip** — откат: первый источник 500, второй мусор, третий валидный IP → берём
   третий; все сломаны → ошибка; IPv4/IPv6 валидация.
5. **ipinfo** — парсинг фикстур ipapi.is и ip-api.com в общую модель; кэш не делает
   повторный запрос в пределах TTL.
6. **leak** — STUN: кодирование Binding Request, декодирование XOR-MAPPED-ADDRESS
   (IPv4/IPv6), проверка transaction ID; полный обмен с локальным фейковым STUN-сервером;
   логика DNS-утечки (страна резолвера ≠ стране выхода → утечка; совпадает → нет;
   публичный резолвер Cloudflare/Google при VPN — не утечка, если страна совпадает);
   timezone-разница.
7. **store** — запись/чтение событий, фильтр `since`, удаление файлов старше 30 дней.
8. **web** — `/api/status` отдаёт JSON нужной формы; `/api/webrtc` принимает результат;
   сервер слушает только 127.0.0.1.

Смоук-тест: `vpnrate -headless` на реальной сети 30 с → `/api/status` возвращает IP,
оценки и хотя бы одну успешную пробу.

## Что выяснилось на живом тесте (2026-11-16)

- **Ложная DNS-утечка.** Выход sing-box в Цюрихе, а Google DNS отвечал из Франкфурта.
  Это соседний PoP публичного резолвера, а не утечка. Добавлено исключение для
  anycast-DNS и тест на этот случай.
- **Гонка WebRTC.** Сразу после перезапуска дашборд успевал прислать кандидатов раньше,
  чем агент узнавал свой выходной IP, и собственный IP засчитывался как утечка. Теперь,
  пока выходной IP не известен, вердикт «неизвестно». Добавлен тест.
- **Ресурсы.** Трей-версия: ~25 МБ рабочего набора, ~0,15 с CPU за первые 45 с
  (большая часть — стартовые TLS-запросы). Exe ~8 МБ.

## Режим прокси (добавлено 2026-11-16)

Клиенты без TUN (v2rayN, Nekoray, Hiddify, Clash) не создают адаптер, а включают системный
прокси Windows (`HKCU\...\Internet Settings`: `ProxyEnable` + `ProxyServer`). Агент читает его
каждые 5 с и, если он включён:
- считает прокси активным VPN-маршрутом (вкл/выкл → события vpn_up / vpn_down);
- пробы связности делает **через прокси** (HTTP CONNECT или SOCKS5), т.е. измеряет путь браузера;
- публичный IP и репутацию запрашивает через прокси;
- STUN оставляет прямым: UDP мимо прокси — реальная WebRTC-утечка, о ней и надо сказать;
- DNS-вердикт = «неизвестно»: браузер резолвит имена на стороне прокси, системный резолвер
  используют только приложения, игнорирующие прокси. Штраф не начисляется.
PAC-скрипты (AutoConfigURL) не поддерживаются.

## Профили подключений (добавлено 2026-11-16)

Профиль = сеть выхода: `AS<номер>-<страна>`. Пользователю ничего не нужно размечать:
переключил VPN/сервер или выключил VPN — история пишется в другой профиль. Каждая минутная
запись хранит профиль, события обрыва и падения VPN — тоже; метаданные (название, через что,
последний Trust) лежат в `profiles.json`. При смене профиля недописанная минута сбрасывается
в старый профиль. Дашборд показывает таблицу за 7 дней: время, аптайм, обрывы, падения VPN,
средняя задержка, Trust; текущий профиль сверху.

Одновременно оценивать два VPN нельзя — трафик идёт по одному маршруту; сравнение копится
во времени.

## Автозапуск (переделано 2026-11-22)

Было: ключ `HKCU\...\Run`, регистрировался один раз при первом запуске (флаг `autostart_set`).
Сломалось: один запуск с `-no-autostart` навсегда помечал «решение принято», и автозапуска не
было вовсе. К тому же Run-ключи Windows запускает поздно и с задержкой.

Стало:
- **Задание планировщика** с `LogonTrigger` для текущего пользователя (админ не нужен),
  без задержки, без лимита времени, не останавливается на батарее, перезапуск при сбое,
  аргумент `-autostart`. Если планировщик отказал — откат на Run-ключ; держим только один механизм.
- **Самовосстановление:** предпочтение `autostart` (по умолчанию вкл.) + путь, который
  зарегистрировали. Каждый запуск сверяет: записи нет или exe переехал → перерегистрация.
- **Дубликат при автозапуске** (порт занят + `-autostart`) выходит молча, без открытия браузера.
- **Ожидание сети:** до первой успешной пробы состояние «ждём сеть», это не обрыв и не идёт в
  аптайм; при появлении сети через ≥10 с — событие `network_ready`.
- Мониторинг до входа в систему потребовал бы службу Windows (установка с правами
  администратора, отдельный процесс для трея) — отложено.

## Живучесть (2026-11-25)

Что нашли на машине автора:
- **Задание автозапуска пропало** между 22.11 и 25.11 (кем — не установлено: журнал
  планировщика и аудит выключены), поэтому после перезагрузок агент не стартовал.
- **Значок «пропадал» при переключении VPN:** в логе ошибки `Shell_NotifyIcon ... timeout`
  прямо перед событиями VPN. Проводник подвисает, пока Windows перестраивает сеть, и может
  потерять значок; библиотека трея восстанавливает его только по `TaskbarCreated`
  (перезапуск Проводника).
- **Цикл проверок замер** 22.11 в 21:25 и ожил 25.11 после выхода из сна — процесс при этом
  жил. Точное место зависания не установлено.

Что сделано:
- **Двойной автозапуск:** задание планировщика + Run-ключ одновременно (дубликат выходит
  молча). Проверка и починка — при старте и каждые 10 минут, с записью в лог, чего не хватало.
- **Хранитель значка:** раз в 10 с `Shell_NotifyIconGetRect`; если значка нет — посылаем своему
  окну `TaskbarCreated`, библиотека добавляет значок заново. Проверено удалением значка извне.
- **Сторож:** если тик не завершался 2 минуты (и это не выход из сна) — дамп всех горутин в лог
  и перезапуск процесса с `-restarted` (новый экземпляр ждёт освобождения порта).
- **Таймауты** на перечисление адаптеров и чтение реестра (3 с); при таймауте сохраняется
  последнее известное состояние, ложного «VPN down» нет.
- **Паники** в шагах монитора и горутинах трея перехватываются и пишутся в лог со стеком;
  `debug.SetCrashOutput` пишет фатальные ошибки в `vpnrate.log` (у трей-сборки нет консоли).

## Релизы

`.github/workflows/release.yml`: на тег `v*` GitHub собирает `vpnrate.exe` (трей) и
`vpnrate-cli.exe` (консоль, для `-headless`) из тегированного исходника, прогоняет тесты,
прикладывает SHA256SUMS. `ci.yml` гоняет тесты на каждый push и PR.

## Демо-режим

`vpnrate -demo` поднимает дашборд на выдуманных данных (IP из диапазонов для документации,
синтетическая история за 24 ч, «живой» обрыв через 20 с после старта) и не делает ни одного
сетевого запроса. Нужен для скриншотов README — чтобы не публиковать реальный IP автора —
и чтобы посмотреть интерфейс без установки.

## Риски и честные оговорки

- Флаги «VPN/datacenter» у бесплатных API неидеальны; рейтинг — ориентир.
- `whoami.akamai.net` может не ответить через некоторые DoH/фильтрующие резолверы —
  тогда DNS-проверка «неизвестно», без штрафа.
- Список неподдерживаемых стран приблизительный и вынесен в константу.
- Бесплатные лимиты: ipapi.is ~1000/день, ip-api.com 45/мин — при запросах только на смену
  IP с кэшем этого с запасом хватает.
